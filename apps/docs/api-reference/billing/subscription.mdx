---
title: GET Current subscription
description: Return the subscription, effective access, usage, and billing period.
---

## Endpoint

```txt
GET /api/v1/billing/subscription
```

```json
{
  "data": {
    "subscription": {
      "status": "trialing",
      "plan": { "code": "starter", "name": "Starter" },
      "trialPlanCode": "starter",
      "trialStartedAt": "2026-07-14T09:00:00.000Z",
      "trialEndsAt": "2026-07-21T09:00:00.000Z",
      "trialConsumedAt": "2026-07-14T09:00:00.000Z",
      "scheduledPlan": null,
      "scheduledPlanAt": null,
      "scheduledAction": null
    },
    "access": {
      "operational": true,
      "reason": "trialing",
      "blockedAt": null,
      "graceEndsAt": null
    },
    "usage": {
      "messagesCount": 0,
      "effectiveOutboundUsage": 0,
      "apiRequestsCount": 0,
      "activeInstancesCount": 0,
      "activeApiKeysCount": 0
    },
    "period": {
      "start": "2026-07-14T09:00:00.000Z",
      "end": "2026-07-21T09:00:00.000Z"
    }
  }
}
```

`access.operational` is the frontend source of truth. Possible reasons are `active`, `trialing`, `cancellation_grace`, `past_due_grace`, `trial_expired`, `payment_required`, `past_due`, and `suspended`.

When access is blocked, product endpoints return `402` (`TRIAL_EXPIRED`, `SUBSCRIPTION_REQUIRED`, or `SUBSCRIPTION_PAST_DUE`) or `403 SUBSCRIPTION_SUSPENDED`. Billing, profile, account deletion, and contact export remain available in the portal.

<Note>`statusesCount` can still appear temporarily for backward compatibility, but WhatsApp Statuses are removed and never contribute to `effectiveOutboundUsage`.</Note>
